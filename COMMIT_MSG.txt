fix(queue): see the whole queue, and actually reach stalled downloads

Two defects, both silent.

1. The queue was never paginated. One request with pageSize=2500 and
   sortKey=status returns only its first page, and 'completed' sorts first, so
   every run examined the same 500-record block and never looked at the other
   ~2,000 records - including every stalled download this script exists to
   clear. fetch_queue() now walks every page; the caller sorts by the added
   timestamp so the per-run caps spend themselves on the oldest work.

2. The stale-download rule sat BELOW an early 'if not status_messages: return
   None', so it could only fire on a record that also carried import-failure
   messages. Lidarr emits no status messages at all for a download that is
   merely in progress or waiting for a slot, which is most of a 2,500-record
   queue.

   Moving the rule up on its own would have been destructive. Lidarr reports
   trackedDownloadState 'downloading' for anything the client has not
   finished, which includes a torrent merely QUEUED behind the download slot
   limit. Measured 2026-09-21: that is 1,289 healthy records against 40
   genuinely stalled, and every delete fires an AlbumSearch. So a record with
   no status messages now only counts as stale when the CLIENT status says it
   is not progressing (downloading/paused). queued and delay never do.

Also: a 30s API timeout cannot survive a full page (~46s per 1,000 records),
which is why every run died on 'ERROR fetching queue: timed out' until the
deployment patched it. It is now API_TIMEOUT=300 upstream, so that runtime
patch is no longer needed.

Because the script now sees the whole queue, the number of matching records is
no longer bounded by the fetch window, so bound it explicitly instead:
max_deletes_per_run=50 (every delete fires an AlbumSearch) and
max_imports_per_run=500. Leftovers are next run's work.

Adds tests/test_classification.py - pure logic, no API, no network - covering
the ordering, the queued-is-not-stale guard and pagination, and runs it in CI.
